# ברכי קרביץ

# מערכת RAG לחברת משחקי הקופסה "שביל החלב משחקים"

תרגיל הגשה בקורס. המערכת עונה בעברית על שאלות של לקוחות על חברת משחקי קופסה בדיונית, על סמך 25 מסמכים בדיוניים בלבד: חוברות חוקים, קטלוגים ומחירים, מדיניות החזרות, משלוחים ואחריות, שאלות נפוצות, והיסטוריית החברה. כשאין במאגר מידע מספיק, המערכת אומרת זאת ולא ממציאה תשובה.

## מה בפנים

- **טעינה ואינדוקס:** מסמכי Markdown ו-PDF (כולל חילוץ עברית תקין מ-PDF) מחולקים לקטעים של 512 טוקנים עם חפיפה של 50, וכל קטע נשמר עם מטא-דאטה: סוג מסמך, שם משחק, תאריך עדכון, גרסה, שם קובץ וכותרת סעיף.
- **מענה על שאלות:** זיהוי שם משחק בשאלה, אחזור 20 קטעים, דירוג מחדש על ידי `gpt-4o-mini` בשתי קבוצות של 10, ותשובה בעברית על סמך 3 הקטעים הטובים ביותר לכל היותר (ורק אלה שהמדרג לא פסל).
- **ממשק:** צ'אט נקי ב-Streamlit בעברית מימין לשמאל. הממשק לא מציג מקורות או נתונים טכניים.
- **יומן פנימי:** שורה לכל שאלה ב-`logs/queries.jsonl`.
- **הערכה:** סט שאלות עם מדדים (Recall@k, MRR, Faithfulness, Answer correctness ועוד), הרצה בפקודה אחת ודוח עם תאריך.

טכנולוגיות: Python 3.12, LlamaIndex, ChromaDB מקומי, `gpt-4o-mini`, `text-embedding-3-large`, Streamlit. הנימוקים ב-[docs/architecture.md](docs/architecture.md).

## שינוי מהמפרט: הסיווג האוטומטי הוסר

המפרט המקורי כלל סיווג אוטומטי של כל שאלה לסוג מסמך (השוואת Embedding לתיאורי סוגים וסינון לפי סף). הסיווג מומש, נבדק והוסר בהוראת המשתמשת, מהסיבות האלה:
- דיוק הסיווג נשאר 70% בשני סטי ההערכה.
- הסף שכויל על 10 שאלות לא החזיק ב-20 שאלות נוספות: הטווח ללא סינון שגוי התכווץ מ-0.062 ל-0.006, והופעלו סינונים שגויים.
- הרצה בלי סיווג נתנה תוצאות זהות להרצה איתו.

הפירוט והמספרים ב-[docs/problems.md](docs/problems.md) (בעיה 9). התאמת שם המשחק נשארה.

## בונוס: השוואת שיטות חלוקה

בוצעה השוואה בין החלוקה הנוכחית (`SentenceSplitter`, 512 טוקנים וחפיפה 50) לבין חלוקה לפי מבנה המסמך (`MarkdownNodeParser`, חלק ארוך מדי מחולק גם לפי גודל, ו-PDF נשארים בחלוקה לפי גודל ומשפטים). 36 שאלות, שתי הרצות לכל שיטה:

| | sentence (ברירת מחדל) | markdown |
|---|---|---|
| Recall@3 | 94% | 89% |
| Recall@10 | 97% | 97% |
| נכונות (שאלות עם תשובה) | 90% | 81% |
| סירובים שגויים | 1 מתוך 31 | 3 מתוך 31 |
| סירובים נכונים (אין תשובה במאגר) | 5 מתוך 5 | 5 מתוך 5 |
| טוקנים ב-LLM לשאלה | כ-3,335 | כ-2,175 |

בסט הקטן הזה השיטה הנוכחית טובה יותר, בעיקר בגלל שתי שאלות על גרסה ישנה שנענו ב-`markdown` בסירוב. ההבדל נבנה מארבע שאלות, ולכן אינו מובהק. **ברירת המחדל נשארה `sentence`**, והחלפתה לא נעשתה. פירוט ב-[docs/evaluation.md](docs/evaluation.md) ובעיה 13 ב-[docs/problems.md](docs/problems.md).

להפעלת השיטה השנייה: `RAG_CHUNKING_METHOD=markdown` (נבנה אוסף Chroma נפרד), או שינוי `CHUNKING_METHOD` ב-`src/config.py`.

## אחזור 20 ודירוג בשתי קבוצות, וכיוונים שנבדקו ולא יושמו

כדי שקטעים נכונים שהאחזור הוקטורי מדרג במקומות 11 עד 20 יגיעו למדרג (בעיה 11), נשלפים 20 קטעים ומדורגים בשתי קריאות של 10. דירוג 20 בקריאה אחת נוסה ובוטל כי המדרג מתקלקל (שאלת מחיר שנענתה נכון 6 מתוך 6 ירדה ל-0 מתוך 6). על 42 שאלות, שתי הרצות לכל תצורה: סירובים שגויים 1 מתוך 36 ← 0 מתוך 36, נכונות כ-91% ← 94%, שאלה 401 מסירוב לתשובה חלקית, סירובים נכונים 6 מתוך 6 בשתיהן. המחיר: כ-76% יותר טוקנים לשאלה.

נבדקו ולא יושמו: חיפוש משולב עם BM25 (שליפת 20 וקטוריים כבר נותנת Recall של 100%, ו-RRF מוריד את קטע המחיר של עמק הדבורים אל גבול ה-10 או מחוצה לו), פיצול שאלה 304 לשתי שאלות (3 מתוך 5), וכלל בהנחיית התשובה נגד שיוך מחיר ערכה למשחק בודד (לא שיפר דבר, בוטל). **המסקנות נכונות למאגר של 48 קטעים בלבד, ולא בהכרח למאגר גדול.** הפירוט ב-[docs/problems.md](docs/problems.md).

## הרצה ב-Windows

### דרישות

- Windows עם PowerShell.
- **Python 3.12.** מאחורי סינון כמו נטפרי, Python 3.13 ומעלה נכשל באימות תעודות ה-SSL (ראו [בעיה 1](docs/problems.md)). התקנה: מתוך מנהל ההתקנות של Python (`py install 3.12`) או מהאתר python.org.
- מפתח OpenAI.

### התקנה

בתיקיית הפרויקט:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env
```

פותחים את `.env` ומשלימים אחרי `OPENAI_API_KEY=` את המפתח, בלי מרכאות. הקובץ אינו עולה ל-git.

### בדיקת גישה למודלים

```powershell
.\.venv\Scripts\python src\check_access.py
```

אמורות להופיע שתי שורות "תקין", אחת לכל מודל.

### בניית האינדקס

```powershell
.\.venv\Scripts\python src\ingest.py --dry-run   # חלוקה והערכת עלות, בלי קריאות API
.\.venv\Scripts\python src\ingest.py             # בנייה (Embedding רק אם האינדקס עדיין לא קיים)
```

הרצה חוזרת טוענת את האינדקס מהתיקייה `chroma_db` בלי Embedding מחדש. `--rebuild` מוחק ובונה מחדש. כל ה-25 מסמכים נוצרים כ-48 קטעים, ועלות הבנייה כ-$0.003.

### הפעלת הצ'אט

```powershell
.\.venv\Scripts\python -m streamlit run src\app.py --server.headless true
```

ופותחים את הכתובת שמוצגת בטרמינל (ברירת מחדל http://localhost:8501). אם הפורט תפוס, מוסיפים `--server.port 8510`.

### שאלה משורת הפקודה (לבדיקה)

```powershell
.\.venv\Scripts\python src\ask.py "כמה עולה עמק הדבורים?"
```

מציג גם פרטים טכניים. אינו חלק מהממשק.

### הערכה

```powershell
.\.venv\Scripts\python src\evaluate.py --label שם                                  # 10 שאלות
.\.venv\Scripts\python src\evaluate.py --questions eval\questions_all30.json --label שם
.\.venv\Scripts\python src\evaluate.py --embed-model text-embedding-3-small --label small
.\.venv\Scripts\python scripts\price_regression.py --runs 5 --label שם              # סט רגרסיה קבוע לשאלות מחיר
```

להשוואה לתצורה הקודמת (שליפה ודירוג של 10 קטעים בקריאה אחת): `$env:RAG_RETRIEVE_K = "10"` לפני ההרצה.

הסקריפט מציג הערכת עלות לפני ההרצה, ודורש `--yes` אם היא מעל דולר. הדוח נשמר בתיקייה `reports` עם תאריך ושעה. להשוואה בין דוחות:

```powershell
.\.venv\Scripts\python scripts\compare_reports.py reports\a.json reports\b.json
```

פירוט ב-[docs/evaluation.md](docs/evaluation.md).

### דוגמאות מהיומן

```powershell
.\.venv\Scripts\python src\ask.py --source examples "שאלה 1" "שאלה 2"
.\.venv\Scripts\python scripts\make_examples.py
```

מפיק את [docs/examples.md](docs/examples.md) מהיומן הפנימי.

### בדיקות נוספות

```powershell
.\.venv\Scripts\python scripts\check_loading.py     # חילוץ ה-PDF זהה למקור (בלי API)
.\.venv\Scripts\python scripts\test_app.py ok        # הממשק: ok, nokey, badkey
```

### בניית קובצי ה-PDF מחדש

מקורות ה-PDF בתיקייה `pdf_src`. הסקריפט `scripts\build_pdfs.py` מפיק אותם ל-`data` באמצעות Microsoft Edge במצב headless (Edge מותקן ב-Windows).

## הגדרות

כל ההגדרות במקום אחד: [src/config.py](src/config.py). שם מודל השפה (`LLM_MODEL`), מודל ה-Embedding (`EMBED_MODEL`), גודל הקטעים, מספר הקטעים שנשלפים (20), גודל קבוצת הדירוג (10) ומספר הקטעים שנשלחים, ורף הרלוונטיות של הדירוג. החלפת מודל היא שינוי בשורה אחת, ולכל מודל Embedding נוצר אוסף נפרד ב-Chroma.

## מבנה התיקיות

```
src/        קוד המערכת (config, loader, indexer, rag, app, evaluate ועוד)
scripts/    כלי עזר: בניית PDF, בדיקות, השוואת דוחות, הפקת דוגמאות
data/       25 מסמכי המאגר (Markdown ו-PDF)
pdf_src/    מקורות ה-PDF
eval/       סטי שאלות להערכה
reports/    דוחות הערכה עם תאריך
docs/       ארכיטקטורה, דוגמאות, בעיות והערכה
logs/       יומן פנימי (לא עולה ל-git)
chroma_db/  האינדקס (לא עולה ל-git)
```

## תוצאות ומגבלות

בהערכה על 42 שאלות (נכונות כ-94%, 0 סירובים שגויים מתוך 36, ו-6 מתוך 6 סירובים נכונים בשאלות שאין עליהן תשובה), על 10 שאלות נוספות, ועל 5 שאלות לקוחה חדשות שנכתבו מראש (נכונות 3 מתוך 4 בשאלות עם תשובה, וסירוב נכון בשאלה ללא תשובה). עם זאת:
- הסטים קטנים, והמספרים אינדיקציה ראשונית ולא מדידה סטטיסטית. המסקנות נבדקו על מאגר של 48 קטעים.
- **מחיר שגוי נשאר בשאלה 304** ("מתנה לילד בן 7"): המערכת עונה 189 ₪, מחיר ערכת המשפחה, ולא 129 ₪ של מסע הצבעים, ב-5 מתוך 5 הרצות (בעיה 12, פתוחה). שאלה 401 על חלק חסר נענית כעת, אבל בתשובה חלקית (בעיה 11).
- בשאלה 605 בסט החדש ("שיחקנו פעמיים, אפשר להחזיר?") המערכת הפכה את משמעות המדיניות (בעיה 14, פתוחה).
- נצפה סירוב שגוי בשאלות בודדות (למשל שאלה 203). המודל אינו דטרמיניסטי לגמרי גם ב-temperature 0.
- ציוני ה-Faithfulness רועשים כי השופט הוא אותו מודל שעונה.

כל הבעיות שנצפו, כולל אלה שלא נפתרו, ב-[docs/problems.md](docs/problems.md).

## אבטחה

מפתח ה-API נקרא רק מ-`.env`. הוא אינו מוצג ואינו נרשם בקוד, ביומן או בפלט, והיומן אינו שומר הודעות שגיאה גולמיות.
